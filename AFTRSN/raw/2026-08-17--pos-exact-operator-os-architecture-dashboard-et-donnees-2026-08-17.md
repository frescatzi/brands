{"# POS-EXACT — Operator OS : architecture du dashboard de mesure (FastAPI   SQLite   front vanilla)\n\n**Date :** 2026-08-17 · **Projet :** Operator OS / LUMINA · **Objet :** documenter l'architecture réelle de l'Operator OS (dashboard de mesure de la stack Hermes), ses 4 vues, ses sources de données, et ses endpoints. Fait suite au déploiement sur luminaos.aftersunpeople.com.\n**Statut :** ✅ VERROUILLÉ ":""," VALIDÉ LIVE.\n\n---\n\n## 1. Architecture générale\n\n- Stack : Python 3.13   FastAPI   uvicorn (port 8090), base SQLite `operator.db`, front SPA vanilla JS   Chart.js (aucun framework).\n- Code : dossier `/opt/data/operator-os/`, modules `app/` (API   front) et `collector/` (agrégation).\n- Déploiement : image Docker via Coolify (repo GitHub privé `frescatzi/luminaos`), domaine `luminaos.aftersunpeople.com`, Basic Auth obligatoire.\n\n## 2. Les 4 vues et leurs sources de données\n\n- Home (`/api/home`) : spend 28j/7j, sessions, ROI (taux horaire × minutes gagnées), coût par provider/modèle. Source : `daily_usage` agrégée depuis les 5 state.db Hermes.\n- Skills (`/api/skills`) : catalogue 243 skills   métriques (usages, succès, valeur estimée). Source : `skill_catalog`   `skill_usage`.\n- Memory (`/api/memory`) : banques pgvector (lumina_memory, aftrsn_memory, karteramaris_memory), skills registry, marques. Source : webhook n8n `memory-dump`.\n- Dream (`/api/dream`) : 4 prescriptions classées sévérité × impact dollar, générées par le modèle Claude. Source : table `dream_prescriptions`.\n\n## 3. Séparation collecteur / serveur (règle d'or)\n\n- Le collecteur (lecture des state.db Hermes   webhook mémoire) tourne SUR LE VPS via cron, jamais dans le conteneur Docker (qui n'a pas accès aux state.db).\n- Le conteneur ne fait que servir l'API et lire `operator.db` (monté sur `/data`).\n- La base est synchronisée du VPS vers le conteneur chaque matin (script hôte `sync-operator.sh`, cron 7h15).\n\n## 4. Sécurité\n\n- Basic Auth via middleware (variables `OPERATOR_OS_USER` / `OPERATOR_OS_PASSWORD`). Sans config, tout accès est refusé (503).\n- Port 8090 jamais exposé en public ; seul le domaine HTTPS via le proxy Coolify.\n- Secrets (clés Anthropic, Postgres) restent dans n8n, jamais dans le code ni le repo.\n\n## Difficultés / Solutions / Lessons learned\n\n### Difficultés\n- Disque VPS plein (100%) pendant le build → helper Coolify bloqué.\n- `/opt/data` n'existe pas sur l'hôte : la base vivait dans le conteneur Hermes.\n- Docker refuse la copie directe entre conteneurs (`docker cp` A→B non supporté).\n\n### Solutions\n- Nettoyage ciblé des volumes orphelins (docker volume rm sur les hash sans lien)   redémarrage Coolify pour relancer le helper.\n- Copie via fichier temporaire hôte : `docker cp hermes:/opt/data/.../operator.db /tmp/` puis `docker cp /tmp/operator.db lumina:/data/`.\n- Cron hôte 7h15 qui refait la synchro chaque matin.\n\n### Lessons learned\n- Toujours libérer le disque AVANT de lancer un build Docker sur un VPS 38 Go.\n- Le build context Coolify doit contenir le code (repo Git), pas seulement le docker-compose.\n- Un déploiement se teste par l'URL publique réelle, pas par le statut affiché par l'UI.\n\n---\n\n*POS-EXACT — 2026-08-17, verrouillé. n8n et le dashboard font foi.*":""}
